Retail-only Android POS · offline-first · Kotlin + Jetpack Compose + Room

Section 1 · Product

Offline-first point of sale for Nepali retail

SajiloPOS runs the whole shop counter on-device: catalog, cart, checkout, receipts and analytics work with no network. Native Android app, retail scope — no business-type switching, no server dependency.

Platform

Native Android (Kotlin), minSdk 24 / targetSdk 36, Material 3 + Jetpack Compose UI, Room/SQLite persistence, CameraX + ZXing barcode scanning.

Money & locale

Nepalese rupees (रू), 13% VAT, 10% optional service charge, Indian digit grouping (1,25,000), Devanagari product names.

Payments

Cash with change math plus eSewa, Fonepay and Khalti dynamic QR with gateway verification before a sale settles.

Quality bar

73 unit tests green, KSP-verified Room queries, emulator-verified screens, bundled offline fonts (Manrope + Inter).

Section 2 · Structure

MVVM with unidirectional data flow

Composables are stateless renderers. All state lives in one PosViewModel, fed by PosRepository, fed by Room. Events flow up as lambdas; state flows down as StateFlow.

Pure logic stays pure

AnalyticsEngine and Format are plain Kotlin objects with zero Android dependencies — fully unit-testable on the JVM.

Side effects stay local

Printing, sharing, clipboard and camera live in thin component-level helpers, never in the ViewModel.

One activity, five tabs, two layouts

MainActivity.kt hosts everything: it collects ViewModel state once and fans it out to tabs, dialogs and the top bar. No navigation library — a single selectedTab state switches destinations.

Section 4 · data/model/PosModels.kt

Small, explicit models

Room entities carry persistence; plain data classes carry UI math. Completed sales are immutable facts — nothing is ever edited, only appended.

ModelRole & key rules
ProductItem @EntityCatalog row: name, Nepali name, barcode, category, price, cost, stock, threshold, unit, industry mode.
CartItemTransient line: product + qty + concession + notes; computes unitPriceAfterDiscount and itemTotal.
SaleTransaction @EntityImmutable receipt: invoice no, totals, method, status, ref, cash tendered/change, item summary.
SaleLineItem @EntityOne physical line per sale — powers top-sellers, velocity, COGS and restock without parsing text.
BusinessSettingsShop profile, PAN/VAT, 13% VAT + 10% service-charge toggles, paper width, currency, industry (always retail).
PaymentMethod / IndustryModeEnums with display names, codes and short labels; fromCode() falls back to cash.

Section 5 · data/local/AppDatabase.kt

Room v2, migrated — never wiped

Three entities (ProductItem, SaleTransaction, SaleLineItem) with an explicit MIGRATION_1_TO_2 plus destructive fallback. Seeded on first launch with a 20-product Nepali demo catalog across retail, restaurant and transport lists (plus tables and routes).

  • Single sajilo_pos_database file — the shop survives load-shedding and reinstalls keep history.
  • KSP compiler validates every @Query at build time; a bad query fails compilation, not runtime.
  • All DAO reads return Flow, so the UI refreshes itself the moment data changes.

Section 8 · ui/viewmodel/PosViewModel.kt

Every screen reads from here

Hot StateFlows for settings, products, cart, dialogs, verification and the InsightsSnapshot (revenue, orders, profit, deltas, goal progress, 30-day trend). Derived money (cartSubtotal → serviceChargeAmount → vatAmount → grandTotal) is computed, never stored.

Section 9 · data/analytics/Analytics.kt

Pure math, zero Android

AnalyticsEngine is a stateless object — same input, same output, testable on plain JVM. It turns raw DAO rows into everything Insights renders.

FunctionWhat it does
buildDailySeries()Fills missing days so charts never lie about zero-sale days.
buildPaymentMix()Cash/eSewa/Fonepay/Khalti revenue shares for the donut.
buildRestockSuggestions()14-day sales velocity → days of cover → order quantity against supplier lead time.
urgencyFor() / ceilToInt()Buckets OUT_OF_STOCK → STOCKOUT_SOON → WATCH → PLENTY; rounds order quantities up.

Section 12 · Printing + capture

Paper trail and barcode intake

58/80mm IRD-compliant receipt preview (ReceiptLine, ReceiptDivider), totals + VAT block, verification QR, then Print (Android PrintManager), Share (text intent) or raw ESC/POS copy for Bluetooth thermal printers.

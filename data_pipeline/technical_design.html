SajiloPOS Data Pipeline — Technical Design

Fetch → analyze → dashboard · pandas + matplotlib + Streamlit

Author: Subodh Sharma

Section 1 · Product

Shop analytics without touching the app

A standalone Python pipeline that pulls collected sales data — from the Django API or straight from a Room database file — crunches it with pandas, charts it with matplotlib, and serves an owner-facing Streamlit dashboard. One command runs everything: ./start.sh.

Two sources, one shape

API mode and Room-file mode both normalize into the exact Room column layout, so analysis is identical either way.

Offline-friendly

DB-file mode needs no server at all — matching the app's offline-first reality. Charts render headless (Agg backend).

App-parity maths

Restock predictions mirror the Android AnalyticsEngine: 14-day velocity → days of cover → lead-time order qty.

Verified live

End-to-end run proven against the real API: register → sale → fetch → 7 CSVs + 4 charts + dashboard serving with zero errors.

Section 4 · fetch_data.py — source 1

Tolerant client for a young API

  • Endpoint fallback: tries /api/v1/sales/ then /transactions/, and /sale-items/ → /sale_items/ → /lines/ — first hit per table wins, 404s are tolerated.
  • Response shapes: bare lists or objects wrapping data/items/results/sales/products; camelCase keys accepted and mapped to Room columns.
  • Auth errors fail loud: HTTP 401 explains the key is wrong (or the header style), with a hint toward SAJILO_API_AUTH.
  • Timestamps: epoch millis, epoch seconds and ISO strings all normalize to one datetime column; the CSV keeps epoch-millis to mirror Room exactly.
  • Empty tables are fine: missing tables produce empty frames with a warning — analysis degrades to empty outputs, never a crash.

Section 7 · dashboard.py — Streamlit

Five tabs for the shop owner

Overview (KPIs + trend + mix + top-5) Sales (daily table + weekly bars + monthly) Products (best sellers + category revenue) Inventory (stock levels + restock list) VAT & Export (13% summary + CSV downloads)
  • Sidebar filters — date range plus category and payment-method multiselects drive every KPI, table and chart.
  • Fast by design — CSV/JSON loads are @st.cache_data-cached; the dashboard never re-runs analysis.
  • Take the data home — every table has a CSV download button for accountants and suppliers.
  • Graceful when empty — no analysis yet, or no sales in range, renders guidance instead of tracebacks.

Section 8 · Operating it

One command, honest failures

Daily use

cp .env.example .env once, fill in one source, then ./start.sh every morning: venv → install (first run only) → fetch → analyze → dashboard.

Automation

./start.sh --no-dashboard --db nightly.db refreshes CSVs + PNGs headlessly for cron jobs and CI.

Failure modes

Missing source → usage error naming the exact vars. Bad key → 401 with a fix hint. Unreachable host → clean exit naming the URL. Bad DB → “not a SajiloPOS database” naming the missing tables.

What commits

Code, docs and .env.example only — .venv/, data/, output/ and .env are git-ignored.

Section 9 · Proof

Proven against the real backend

  • Generated a 60-day synthetic shop DB (526 sales, 982 lines) with the exact Room schema; DB-mode fetch + analyze produced 7 CSVs + 4 charts with a sane summary.
  • Ran the pipeline in API mode against the live Django server: register → product → sale → fetch → analyze, all green.
  • Caught and fixed two real bugs on the way: an unhashable endpoint table and ISO timestamps wiped by numeric coercion.
  • Dashboard served headless with health-check 200 and zero tracebacks in the log.
